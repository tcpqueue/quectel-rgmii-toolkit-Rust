# 安装后无法打开网页

## 先收集报告

连接 ADB，完整解压安装包，双击 `SimpleAdmin-Setup.exe`，选择设备后点击 **故障诊断**。完成后点击 **查看报告**。也可以使用命令行入口 `diagnose.bat`。无需先升级或卸载旧版。报告保存在电脑的 `logs/simpleadmin-日期-时间-进程号.txt`；目录不可写时改用 Windows 临时目录。

设备助手无法启动时，可使用 `toolkit-cli.bat` 进行命令行安装。图形界面依赖 Windows 10/11 的 .NET Framework/WPF；不需要另装 WinUI 运行库。安装包须完整解压，不能只复制设备助手 EXE。

诊断只查看平台、文件权限、剩余空间、服务状态、监听端口、防火墙和网络地址，再通过临时 ADB 转发访问公开页面。不会登录、打开 AT 串口、读取短信/凭据、修改配置、重启或重新安装。设备上只上传一个临时诊断脚本，结束后删除。

报告包含 ADB 序列号、IP、MAC 和路由信息。对外分享前可以遮盖这些标识。不会收集 `simpleadmin.auth`、转发平台密钥或完整系统日志。

## 根据结果定位

| 报告或现象 | 判断与下一步 |
| --- | --- |
| 找不到设备、unauthorized、offline | 检查 USB 线、驱动和 ADB 授权；默认只连接一个设备，多设备时用 `ANDROID_SERIAL` 指定目标 |
| 安装包校验失败 | 重新下载并完整解压，不要混用不同版本的 `development` 文件 |
| 非 root、架构不兼容、空间不足 | 安装器会在停止原服务前退出，先核对固件和空间；当前只完成过 RM520N-EU 实机适配 |
| Service 为 failed、ExecMainStatus 非零 | 查看报告末尾的启动错误；旧版丢弃启动错误，没有该文件属于正常情况 |
| 80 端口被其他程序监听 | 确认是否还有其他后台；安装器仅清理识别出的旧 SimpleAdmin 或原厂 lighttpd，不会强杀未知服务 |
| WEB_CHECK=FAIL | 模块本机无法取得正确页面，优先检查服务、端口和静态文件 |
| PC_HTTP_CHECK=OK，但模块 IP 打不开 | 应用已通过 USB/ADB 访问；检查当前 LAN IP、电脑网卡与网段、路由、固件防火墙/IP 透传模式 |
| 浏览器自动跳到 HTTPS | 当前默认只监听 HTTP 80，请使用 `http://`；检查浏览器的 HTTPS 强制升级设置 |
| 登录密码错误 | 升级保留原密码，`admin/admin` 只适用于首次安装或无效认证文件被重建的情况 |

安装器成功后显示一个 `http://127.0.0.1:端口/` 地址，可直接在连接 ADB 的电脑上使用。端口由 ADB 自动分配，不占用其他已有转发。诊断模式会移除自己创建的临时转发。

## 本次修复的安装边界

- systemd 与后台模式共用 TCP 80 防火墙准备步骤；规则插入失败不再静默忽略。
- 安装前检查包内文件 SHA-256、可执行文件能否启动、root 权限及空间。先复制并校验新程序和页面，再停止旧服务。
- 复制等命令失败立即返回失败，尽力同步并恢复根目录只读；硬断电或介质故障仍可能中断替换，本安装器不承诺跨断电事务回滚。
- 真实读取首页、登录页与登录页语言脚本。首页允许正常的 `/login.html` 登录跳转，两个公开资源必须返回 HTTP 200 和正确标识；systemd 的 active 状态或单纯存在进程不能单独作为成功条件。受保护的首页资源通过安装文件校验验证，不为检测而登录或绕过认证。
- 无法安装开机自启动会明确报错；systemd 成功时清理旧的 post_boot 自启动块，避免重复启动。
- 默认保留现有网桥 MAC 和 QCMAP 配置，不自动重启。旧版安装已经修改过的网络配置不会自动恢复。
- 模块启动错误仅保存到 tmpfs 的 `/tmp/simpleadmin-startup.log`，不持续写 NAND；完整安装过程保存在电脑报告中。

2026-09-06 在 RM520N-EU 复查：固件使用 Bash 3.2，网页检查已去掉新版本 Bash 专属语法。停止旧服务时不再执行旧停止脚本或信任 PID 文件，改为核对 `/proc/PID/exe`，强制结束前再次核对进程启动时间，避免 PID 复用和命令文字误匹配。

最终修正版已完成真机在线升级，服务 active、自启动 enabled、模块本机与电脑 ADB 通道 HTTP 检查均通过；安装前后 boot_id 一致，根目录恢复只读。未进行短信发送或删除测试。原始报告中的设备重启没有保留下重启前的进程证据，因此不能确定最初的具体触发进程。
