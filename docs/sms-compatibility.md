# 短信兼容性与验证范围

适用于 Rust 0.2.6、Windows 工具 1.3.2。

## 参考版本

此前下载的发布包为 [VoHive v1.5.4](https://github.com/iniwex5/vohive-release/archive/refs/tags/v1.5.4.zip)。收发实现核对使用用户提供的 [vohive-fork 源码](https://github.com/oneisall8955/vohive-fork/tree/638c9af17430aa4b10e5b83df76108658ee83241)，固定提交 `638c9af17430aa4b10e5b83df76108658ee83241`。发布包不含完整后端源码，不能将 fork 的全部实现称为 v1.5.4 原始源码。

VoHive 面向移远高通模块提供了专用适配，并有 AT、QMI、MBIM 后端。`internal/backend/factory.go` 的默认模式为 AT。本次对齐的是 AT 短信路径，不新增 QMI/MBIM，不改变 USB 网络模式或拨号设置。

## 发送

- 单独发送 `AT+CMGF=0`，确认成功后发送 `AT+CMGS=<TPDU 字节数>`；等待 `>`，写入完整 PDU 和 Ctrl+Z。
- SMSC 长度为 `00`，使用模块配置的短信中心；CMGS 长度不计 SMSC 字段。TPDU 不额外指定有效期，与 VoHive 默认编码一致。
- 自动选择 GSM-7 或 UCS2。GSM-7 单条最多 160 个 septet，长短信每段最多 153；UCS2 单条最多 70 个 UTF-16 单元，长短信每段最多 67。扩展字符和代理对不跨段拆开，最多 255 段。
- `10086`、`888` 等不带 `+` 的短号码保留原样，地址类型为 `0x81`。普通本地号码仍按 SIM 国家码补全，国际号码保留 `+`。
- 相邻分段间隔 500 ms。成功要求同时收到合法 `+CMGS:` 回执和 `OK`；这一点比参考代码的成功判断严格，避免将仅设置模式成功误报为短信发送成功。
- 模块拒绝准备或发送请求时不提交 PDU；等待输入提示超时会发送 ESC 退出输入。发送结果不明确时，不自动补发本卡短信，避免重复计费。

## 接收与删除

设置 PDU 模式和 `AT+CNMI=2,1,0,0,0`，收到 `+CMTI` 时唤醒转发检查，保留十秒轮询补漏。通过 `AT+CPMS=?` 确认可读的 ME/SM 存储，分别读取 `AT+CMGL=4`。存储选择和读取在同一个 AT 工作线程事务内执行，成功、失败均尝试恢复此前的读取存储区，不更改写入和接收存储区。

VoHive 的 AT 路径同时有 CMTI/CMGR 单条读取与 CMGL 全量读取。本项目采用通知触发的全量快照，便于继续按完整收件箱去重和校验删除指纹，不是逐条 CMGR 的逐指令复制。取消每次读取强制执行 `CSMS=1` 的旧逻辑，不自动改写短信中心、IMS 或运营商配置。

前后端及自动删除凭据均携带 ME/SM 存储区，同一区的索引才可用于删除。旧版未记录存储区的删除凭据按 ME 读取，保留旧指纹兼容；无配置变化时不写 NAND。

保留既定产品规则：收件箱首次完整读取只建立基线，不补发已有短信；未确认成功的分段不自动重发；可选在全部渠道转发成功一天后删除，删除前校验存储区、索引和指纹。不采用参考项目读取后立即删除短信的行为。二进制短信仍显示十六进制，不移植其 OTA 分类、语音或 STK 功能。

## 离线验证

`tests/fixtures/vohive-sms-submit.json` 由固定 fork 的 `pkg/smscodec.BuildSubmitTPDUsWithOptions` 生成，使用其依赖 `github.com/warthog618/sms v0.3.0`。覆盖中文 68/70/71 字、GSM-7 160/161 septet、扩展字符跨段边界、短号码、中英俄阿文本。固定连接引用为 1 后，Rust 逐字节核对 TPDU 与 CMGS 长度。

接收用例包含 fork `pkg/smscodec/pdu_trim_test.go` 的 GSM-7 spare-bit 样本及存储填充；另验证 UCS2、同号不同存储区、长短信、去重和删除凭据。Linux PTY 模拟串口验证分步握手、302 拒绝、不提前提交正文、ME/SM 读取失败及删除失败后的存储恢复、分块到达的 CMTI 通知。

短信功能仅进行模拟验证，不进行真实短信收发或删除测试。按用户后续要求，最终 0.2.6 后端和配套短信页面已同步到 RM520N-EU，核对运行版本、文件 SHA-256、服务和 HTTP 页面均通过，根目录恢复只读；该部署检查不触发短信发送接口。

模拟结果能证明协议构造与程序控制流程，不能证明具体 SIM、固件、IMS/运营商短信业务可用，也不能据此宣布此前实机 CMS 302 已解决。
