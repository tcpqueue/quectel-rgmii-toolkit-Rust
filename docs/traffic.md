# 上传与下载统计

适用于 Rust 0.2.7 及以上版本。

总览通过 AT+QGDNRCNT? 读取模块的数据计数。移远 RG520N、RG525F、RG5x0F、RM5x0N 系列 AT 手册第 198 页定义的返回顺序为发送字节数、接收字节数。参见 [移远手册](https://forums.quectel.com/uploads/short-url/x7O7XpZA1jJboG9xct7VxaeWLXx.pdf#page=199)。

例如，返回 +QGDNRCNT: 1024,8192 时，累计上传为 1024 字节，累计下载为 8192 字节。0.2.6 及之前版本把这两个字段反向解析，累计流量、速率、趋势图和近五分钟流量占比都会显示为相反方向。0.2.7 从后端解析处修正，前端的字段名称与布局保持一致。

接收计数对应 nr_rx_bytes、累计下载和下载速率；发送计数对应 nr_tx_bytes、累计上传和上传速率。后台每五秒采样一次，按两次有效 AT 采样的计数差和实际时间差计算速率；五分钟占比按窗口内有效采样区间的上下行字节数计算。该统计是模块 AT 数据计数，不等同于运营商账单。

## 回归验证

Rust 测试覆盖发送、接收方向不对称、单方向为零和双方向为零的解析，以及从 AT 返回值到采样速率、趋势点与占比的完整处理链路。tests/traffic-ui.cjs 核对页面累计流量与速率绑定、图例方向和图表单位。tests/traffic-direction-browser.cjs 通过模拟服务检查原始 AT 返回值、解析字段、总览 API 和实际页面的累计下载、累计上传数值。历史 Go 回归样本原文件保留，测试只纠正其中四个方向颠倒的预期字段。

本次验证使用离线样本和模拟服务，未在真实模块上执行下载或上传测速，也未重置或写入模块流量计数。
