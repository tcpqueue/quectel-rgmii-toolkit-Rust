# 离线时网页响应

v0.2.1 的 Ping 监测每秒调用一次系统 DNS。异步等待超时后，底层阻塞查询仍可能继续占用 Tokio 工作线程；连续慢查询会占满 4 个线程，导致静态网页读取排队。表现为首页跳转仍能返回，登录页却超时。没有插卡并不必然触发，关键是系统 DNS 查询长时间不返回。

修复后 DNS 使用独立工作线程，同时最多执行一个查询。900 毫秒等待超时后保留原查询，下一次采样继续等待；解析失败后间隔 5 秒重试，成功结果缓存 60 秒。IP 目标直接使用，不执行 DNS。修改目标后不会使用旧域名的结果，也不会额外堆积线程。持续卡住的系统 DNS 仍会影响域名 Ping，但不占用网页文件读取线程。该处理不写入 NAND。

在 Linux 原生项目目录构建调试程序后运行：

```sh
cargo build --locked
node tests/offline-dns.cjs
```

测试需要 GCC，通过仅对子进程生效的解析函数替身模拟 DNS 立即失败、25 秒阻塞和 IP 目标，验证首页、登录页及语言脚本可访问，并检查查询数量。不会改变宿主机 DNS，也不连接真实 AT 设备。
