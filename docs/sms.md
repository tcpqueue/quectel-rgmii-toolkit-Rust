# 短信服务与转发

## 配置

1. 在短信页启用短信功能。开关控制应用的短信读取、发送接口及自动转发，不改变 SIM 卡的运营商接收能力。
2. 在同一页的“转发设置”填写设备名称，选择平台，按表单旁的独立教程填入凭据并启用渠道。
3. 保存配置，网络渠道可使用“测试推送”验证。本卡短信渠道不提供测试按钮，正常转发会通过本卡发送并可能产生费用。
4. 启用顶部的转发开关，完成首次收件箱读取后开始识别新短信。

| 平台 | 凭据 |
| --- | --- |
| Server酱 Turbo | SCT 开头的 SendKey |
| 企业微信群机器人 | `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=...` |
| 钉钉群机器人 | `https://oapi.dingtalk.com/robot/send?access_token=...`，可选签名密钥 |
| 飞书群机器人 | `https://open.feishu.cn/open-apis/bot/v2/hook/...`，可选签名密钥 |
| Webhook | HTTP/HTTPS 地址，可选完整 Authorization 请求头，例如 `Bearer ...` |
| 本卡短信 | 一个接收号码，建议使用国际格式；本卡需要支持短信发送 |

已保存的密钥和 Webhook 地址不回传到浏览器。输入框留空保留原值，清除凭据后点击保存才会删除。机器人启用了关键词校验时，可将 `SMS` 或设备名称设为允许的关键词。服务器证书正常验证，HTTP 重定向不跟随；平台业务错误也视为失败。

## 转发行为

本卡短信的 PDU 分段、未确认不重试和循环防护规则见 [新版短信说明](sms-cell-lock.md)。下方的 1,200 字节分段和网络重试描述适用于网络推送渠道。

向所有启用渠道推送新收到的短信，发送箱内容不参与。号码、接收时间及正文从模块读取，设备名称由用户配置。带 UDH 的长短信只有分段齐全才进入队列，不推送不完整正文。

单次推送正文最多 1,200 UTF-8 字节，较长短信使用编号分段。成功的分段不会在同一任务重试时重发。网络中断、限流、服务器异常或业务错误会在三分钟窗口内退避重试；明确的 HTTP 客户端错误终止任务。网络超时后无法判断远端是否已接受通知，个别平台可能重复通知；Webhook 接收方可使用幂等键消除这类重复。

重启、关闭后重新启用转发或变更渠道时，以首次完整读取的当前收件箱作为基线，已有短信均不补发。每十秒检测新短信，首次读取前收到的短信也属于基线。重启时未完成的内存任务不会恢复。停用短信或转发会清空等待任务；仅修改自动删除选项不会清空重试。

等待队列最多 64 个渠道任务，按任务累计的正文预算不超过 256 KiB；一个正在发送的任务独立于等待队列。去重集合最多 4,096 个分段指纹，近期结果最多 50 条，不保存正文。容量达到上限时显示失败结果。

## 自动删除

默认关闭。某条短信在全部启用渠道、全部推送分段都确认成功后，才建立删除任务；任一渠道失败或队列溢出时不建立任务。

以最后一个渠道确认成功的时间起算，24 小时后按分钟检查。删除前重新读取短信，逐个核对存储位置和指纹，全部匹配才执行；已被手动删除或位置被其他短信占用时取消任务。部分删除失败时保留尚未删除的分段继续检查。关闭选项会取消已有删除计划。

删除凭据位于 `sms-delete-receipts.json`，权限 `600`，最多 64 个任务、合计 512 个短信分段。只记录指纹、存储位置、确认时间，不写正文。变化按分钟合并，执行根目录 rw、原子写入、同步、恢复 ro；无变化不写。突然断电可能丢失最后一分钟未落盘的删除计划，此时保留短信，不因缺失凭据而删除。

## Webhook 格式

使用 JSON POST。`text` 是当前分段正文，`part` 从 1 开始；同一短信的所有分段共享 `id`。

```json
{
  "event": "sms.received",
  "id": "message-fingerprint",
  "device": "RM520N-EU",
  "sender": "10086",
  "received_at": "26/09/06,12:00:00+32",
  "text": "示例短信",
  "part": 1,
  "parts": 1
}
```

请求包含 `Idempotency-Key: <id>-<part>`。任意 2xx 状态码表示该分段已接收，建议接收端保存幂等键，并在可靠接收后响应成功。

## 参考与验证

功能调查使用指定的 VoHive Release v1.5.4 压缩包，以及 [vohive-fork](https://github.com/oneisall8955/vohive-fork/tree/638c9af17430aa4b10e5b83df76108658ee83241) 的通知与短信功能。Rust 实现独立编写，不包含其 Go 代码。当前范围仅包含短信，不含 STK、eSIM 或其他模块管理功能。

收发、自动转发、错误重试、自动删除使用模拟 AT、临时文件及本地 HTTP 接收端测试。真机仅检查安装、页面、只读数据和服务状态，不发送或删除用户短信。外部平台需用户填入实际凭据后验证连通性。
